# M9: final QA

The whole site after M0–M8, checked against the real local backend (PostgreSQL 16, all migrations, `ADVIBE_EXTERNAL_MODE=mock`) and the CI's intercepted backend.

## Fixed during QA

| Finding | Fix |
|---|---|
| The sign-in, sign-up, verify, forgot-password and reset-password card still used the pre-redesign palette (`slate`, `blue-700`, hex colours). It also had a redundant "AdVibe · Secure account" line, the same generic text in every mode, and a "Sign in" link on the sign-in page. | Rebuilt on the design tokens: a font-heading title, `controlClass` fields, the primary Button, and success and danger message styles. Each mode has its own one-line intro, and the links below the form fit the page ("Create an account", "Forgot password", "Back to sign in"). Labels, button names, endpoints and logic are unchanged. |
| Auth pages shifted on load (CLS up to 0.26 on phones). The Suspense fallback was one line of text that the full card replaced. | The new `AuthFallback` is the same size as each mode's card. CLS is now 0.000 on all five auth pages at 390 and 1440 px. |
| Signup and reset didn't mention the 12-character minimum until submitting failed. | Added the hint "At least 12 characters." and linked it with `aria-describedby`. |
| The privacy notice said dashboards "use fictional records persisted in browser storage". The terms said "account creation … not active". Both are false now. | Rewrote those sentences to describe what the platform does today. "Legal approval pending" stays, and these are still previews, not final policies. |
| The 404 page and the root loading screen used the old palette and said "This route does not exist yet". | Moved to the tokens, with plain copy and the primary button. |
| The driver portal's error box used `red-*` classes. | Danger tokens. |
