# M3: shared portal shell

## Scope

One application shell (`src/components/portal/portal-shell.tsx`) used by the advertiser, driver and admin portals, plus shared sign-in gate and loading screens (`src/components/portal/portal-access.tsx`). Page content inside the portals is unchanged; that is M5–M7.

## What changed

- **Sidebar:** the AdVibe logo on ink (as `docs/BRAND.md` requires), the portal name, icons for every item, and groups ("Billing and reports", "Earnings and activity", "Finance and governance", "Account"). The ink column runs the full page height and the menu stays in view (fixes audit finding MD2). Admin uses denser rows.
- **One accent colour:** the current page is signal blue in every portal (the purple admin and per-portal colours are gone, finding MD1).
- **Header:** breadcrumbs (portal › section › detail), a notifications link, "Signed in as …", sign out, and for admin an "MFA-protected session" note. The advertiser's business switcher moved into the header.
- **Mobile:** a "Menu" button opens the same navigation in a focus-trapped panel that closes on Escape or after choosing a page, and returns focus to the button. The driver portal's horizontally scrolling tab bar is gone (finding MD5).
- **Page header:** one `h1` per page in sentence case, from the navigation label, with page actions (Refresh, Download CSV) beside it. The all-caps eyebrow labels ("ADVERTISER WORKSPACE", "SERVER-BACKED ADMIN OPERATIONS", "DRIVER / BACKEND") are gone.
- **Navigation labels:** sentence case without "&" ("Profile and settings", "Users and roles"). Every link target is unchanged.
- **Sign-in gate:** one design for all portals (logo, title, the portal's own message, sign-in link, retry where the portal had one). Titles, messages and links are unchanged.
- **Skip link:** "Skip to main content" on every portal page.

## Tests changed and why

- `scripts/b22-live-browser.mjs`
  - Its "signed in" markers were the old header texts ("Advertiser workspace", "Server-backed Admin operations", "LIVE API"), which the shell replaces. It now waits for the role's portal navigation and the "Sign out" button. Same purpose: prove the signed-in portal rendered.
  - It also failed **before any redesign work** (verified on commit `c264088`): `getByLabel("Creative", { exact: true })` never matched, because the label wraps the select, so the accessible name includes the selected option. It now uses `getByRole("combobox", { name: /^Creative\b/ })`, the same element. This went unnoticed because GitHub Actions has not been running.
- No security or release-gate assertion was changed.
