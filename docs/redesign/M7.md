# M7: admin portal

Dense tables, review queues with keyboard shortcuts, right-aligned rupee amounts, and a confirmation step before every audited decision. Permissions, endpoints and request bodies are unchanged.

## What changed

Shared pieces live in `src/features/admin-live/common.tsx`, now built on the design system: `Table` (dense, numeric columns right-aligned with tabular numerals), `Confirm` (dialog), `Tag` (plain-language status badges), `humanize` (API keys to sentence case), `Card`, `Alert`, `FetchState` and `Pager`.

| Page | Change |
|---|---|
| Dashboard | Counts with readable labels ("New users", not "newUsers"). Money is a two-column table with right-aligned rupees ("Confirmed bookings (gross) ₹370.00", not "confirmed Booking Gross Paise 37000"). |
| Campaigns, Approvals | Review queues are tables. **j / k** move, **Enter** opens, **Esc** closes. The keys are ignored while typing or when a dialog is open. "Record reviewed decision" now opens a confirmation dialog repeating the reason. "Reject" is shown in red. |
| Driver partners | Application table, details as a description list, documents as a table. **The browser `window.prompt` for document decisions is replaced** by a dialog with a labelled reason field (at least 8 characters). |
| Users, Advertisers | Account table with search and filters. "Manage" opens a dialog that needs an audit reason of at least 20 characters. |
| Support | Ticket table. Advancing a ticket's status now asks for confirmation. |
| Locations | City, zone and location tables. **The browser `window.confirm` for publishing and archiving is replaced** by a dialog. |
| Pricing | Rate and tax tables with right-aligned amounts. The rate form shows the rupee value next to the paise entry, and saving asks for confirmation. |
| Screens, Ad formats, Audit, Payments, Bookings, Settlements, Notifications, Settings | Tables and plain copy. Engineering wording ("Part 7", "PostgreSQL", "backend-submitted", "mock storage adapter") is gone. Payments, payouts and devices remain switched off and say so. |

- The admin menu descriptions were rewritten in plain language and no longer promise features that don't exist (for example "discounts" and "reach analytics").
- Admin buttons and fields are 44 px tall on phones and 40 px on larger screens.

## Behaviour that did not change

The same six flows were recorded before and after the change against an intercepted backend. The eight mutations are **byte-for-byte identical**: same method, path and body, each with a CSRF token and an idempotency key.

| Request | Body |
|---|---|
| `PATCH /admin/users/:id/status` | `{expectedStatus:"ACTIVE",status:"SUSPENDED",reason}` |
| `POST /admin/campaigns/:id/decision` | `{decision:"rejected",reason,expectedRevision:3}` |
| `POST /admin/creatives/:id/decision` | `{decision:"approved",reason}` |
| `POST /admin/driver-documents/:id/decision` | `{decision:"verified",reason}` |
| `POST /admin/driver-applications/:id/decision` | `{decision:"approved",reason}` |
| `POST /support/tickets/:id/messages` | `{body,visibility:"PUBLIC"}` |
| `PATCH /admin/support/tickets/:id` | `{expectedVersion:1,status:"IN_PROGRESS"}` |
| `POST /notifications/:id/read` | `{}` |

The only difference in the flows is the extra confirm click. No native browser dialogs appeared and there were no page errors.

**Page-load requests**, captured on all 18 admin pages against the real backend, are identical to M5.
